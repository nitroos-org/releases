Why NitroOS

We want an open-source operating system that runs Windows software well enough to use every day. Done by hand, that is the work of decades. With AI coding agents, we think it can be months.

The problem

Windows compatibility is enormous: thousands of APIs, the kernel and driver model, file systems, and thirty years of programs that depend on exactly how all of it behaves. Building that in the open, by hand, takes a very long time. The ReactOS project has been doing it since 1998, and its work is what makes NitroOS possible: the kernel, the Win32 subsystem and most of the user mode come from ReactOS and its contributors.

Our bet

AI coding agents change the speed. In NitroOS, agents investigate bugs, write code and tests, and review each other's work around the clock, under a human maintainer who sets priorities and approves every release. The first NitroOS release came out on 20 October 2026; three weeks and six releases later, Chrome, Firefox, Edge, VS Code, PowerShell 7 and .NET Framework 4.8 programs run, and 32-bit and 64-bit programs run side by side.

We are finding out how far this goes, in the open.

What we optimise for

  • Daily use. The programs people actually use come first: browsers, developer tools, PowerShell, .NET, and Office next. A bug that stops a real program beats a gap that nothing uses.
  • Batteries included. NTFS by default, the firewall on, PowerShell 7 preinstalled, more software one click away in Features. We make the choices; you can change them.
  • Measured, not claimed. Speed is benchmarked and published, including where we are slower. Compatibility claims come with screenshots.
  • Ship often. A release every week or two, each with its full changelog.

The rules we keep

  • Behave like Windows. Where behaviour is unclear, we measure it on a reference Windows installation with test programs we write, and match it, including in security.
  • Clean room. Public documentation, Wine, Unicode CLDR and other open sources only. Never leaked Microsoft code, never Microsoft SDK headers, never values copied out of Microsoft programs.
  • Every change reviewed and tested. A different AI model reviews every change, builds and test suites must pass, and real applications are used as smoke tests before anything lands.
  • Open source. GPL, like ReactOS. ReactOS does not accept AI-generated contributions, and we respect that: we do not submit our changes upstream. How we work is in our AI policy.

Where it stands

NitroOS is alpha software, tested in virtual machines. Some apps still fail, and the known limitations are listed with every release. The next release goals say what we are working on now.

Join in

Try it in a virtual machine and report what breaks. Patches are welcome at nitroos-org/reactos, including AI-assisted ones (say so in the pull request); see CONTRIBUTING.
